# OMF Battlegrounds — Reverse Engineering Findings

Goal: native macOS reimplementation of the "DE" engine (Diversions Entertainment, 2003) that runs the original game data, ScummVM/OpenOMF style. Original binaries are reference only; they are never shipped or patched.

Evidence key: **[REA ev_…]** = REA evidence ID · **[ghidra]** = headless Ghidra 12.1.4 export in `re/dump/<module>/` · **[shell]** = plain `strings`/`xxd`/PE-header observation · *inference* = not directly observed.

## Findings ledger

1. **Exports carry full MSVC-mangled C++ names**, so class and method names are recovered. Engine classes use the prefix `DE_C`. [ghidra `re/dump/Input2/exports.tsv`]
2. **Input2** implements `DE_CDirectInputControllerComponent` (GetAxisState, GetButtonState, HasStateChanged, GetNextStateTime…) and is registered via `DE_CInitInputModule2Factory`. It has 325 functions and 32 classes. [ghidra]
3. **Object model:** `DE_CObject`, `DE_CObjectFactory`, `DE_CContents`, `DE_CReferenceOrigin/Target`, `DE_CGUID`, `DE_CRegistry`, `DE_CDataBlock`. Modules register factories into Core. [ghidra Input2 classes.txt]
4. **All game data is in 65 `.DEObjects` files (728 MB).** [shell]
   - Header: u32 length 0x27, then `"Diversions Entertainment Objects File2"`, then `00 02 00 00 00 00`.
   - Strings are u32-length-prefixed, length including the NUL.
   - Objects carry 16-byte GUIDs; the node suffix `…004033de174c` is common to them.
   - Objects carry type paths such as `TransferAgent\Win\File` and `UniqueActorProperty\Force\Common`.
5. **Payloads are compressed.** `Creature.DEObjects` contains an LZ-style stream with visible literal runs. [shell] Core has `DE_CLZRWContentsCompressor` (LZRW family) and `inflate 1.0 Copyright 1995-1996 Mark Adler` (zlib). [shell strings]
6. **The game logic is scripted.** The `Creature` "Health" Behavior's payload contains C-like source (`float m_…; // This is how much health the creature has`). Core contains the compiler and VM: `DE_CPCodeMethod`, `DE_CClassCompiledMethod`, `DE_CClassExecutorInstance::ExecuteInstant`, and messages such as "began compiling", "did not compile correctly therefore brain cannot run" and "…VMCode was saved…". [shell strings] *Inference:* most gameplay is script ("brains") loaded from data, so an engine reimplementation plus a script VM could run the original content.

7. **Container layout (verified on Creature.DEObjects by `engine/tests/de_tests.cpp`):** `string` signature (`…File` or `…File2`), then for File2 a `u8` format version (2). For version > 1 the master object's vtable+0xAC reads a field (4 zero bytes in shipped data). Then the header `block` and the body. [ghidra Core 0x70051bb0 `DE_CTransferAgentWinFile::LoadHeader` + test]
   - `string` is a `u32` length that includes the NUL, followed by the bytes. [ghidra Core 0x70019b80 `Extract(char**)`]
   - `block` is a `u32` length followed by raw bytes. [ghidra Core 0x70019c10 / 0x70019c90]
   - The header block opens with the `DE_CTransferAgent::ProcessHeader` version byte (9 in shipped data) and a squeezed size. Version 9 calls the master object's `ProcessContents` (vtable+0xA0), then the agent's own, then a count of child object-infos. [ghidra Core 0x70055a70]
   - *Inference:* every class level writes a nested chunk of version `u8`, squeezed size, then fields (seen as `04 41 …`, where 0x41 tracks the name length).
8. **Squeezed integer:** a byte below 0xFE is the value itself; 0xFE is followed by a `u16`, 0xFF by a `u32`. [ghidra Core 0x70019a60 `ExtractSqueezed`]
9. **`DE_CContents::Decompress` methods** (squeezed ID): 0 = stored `block`; 1–3 = `DE_CCompression` LZSS tree coder; 4 = unknown; 5 = rejected; 6 = squeezed size + LZRW3-A; 7 = 16-byte checksum + squeezed size + LZRW3-A. [ghidra Core 0x7001a3b0]
   - **The method-7 checksum is MD5 of the decoded bytes**, verified on Creature: `4dc5475a83156c70d14d398d093d6c1e`. [test]
10. **The LZRW3-A decoder is the standard algorithm:** 4096 slots in 8-way sets, START_STRING `"123456789012345678"`, FLAG_COPY = 1. The binary's hash multiplier (`0x…FE5F`) shares its low 13 bits with 40543, so the results are identical. [ghidra Core 0x7000c200 → `engine/src/de/lzrw3a.cpp`]
11. **Behaviors are stored as script source.** The Creature "Health" behavior decodes to sections `Import`, `Global` and `Members` (`float m_Health; // …`) plus methods such as `HealthChanged`, each with its source text. [test]
12. **Ghidra issue:** its "Non-Returning Functions – Discovered" analyzer wrongly flagged `DE_CDataBlock::DE_CDataBlock`, `operator delete`, `_gAllocateMemoryDebug` and others in Core. That truncated 4,729 call sites and left code undisassembled, including `DE_CTransferAgentWinFile::LoadHeader` (0x70051bb0), which references the file signature. Fix: `re/scripts/NoReturnOff.java` pre-script plus `re/scripts/reexport.sh`. [ghidra]

13. **The DLLs contain full COFF symbol tables.** Core has 49,689 entries, including 19,071 functions, which name static and internal functions too. [shell `re/proto/coffsyms.py`]
    - The symbol values are already RVAs. Ghidra 12.1.4 adds the section VA on top, so every COFF label lands `+0x1000` too far in `.text` (and by the section base in `.rdata`/`.data`).
    - Proof: for all 8,320 Core exports the export RVA equals the COFF value, and the same holds in the other 8 modules.
    - Example: the real `DE_CTransferAgent::ObjProcessContents` is at 0x700545B0, while Ghidra labelled 0x700555B0.
    - Fix: `re/scripts/FixCoffSymbols.java` pre-script, which moves labels and entry points using `re/coff/<module>.tsv`.
    - **Dumps made before this fix carry names shifted by one page for non-exported functions. Trust only post-fix dumps.**

14. **The header is a table of contents.** [ghidra Core 0x700545b0, 0x700557c0, 0x7004fdd0 + `engine/src/de/objects_file.cpp`]
    - After the agent chunk (v9) come the master object info, the agent's own chunk (v1: block, GUID, GUIDPool, BOOL), an `i32` count, then one object info per object.
    - Object info v4 holds: name `string`, class/factory path `string`, GUID, BOOL (1 byte), `i32`, `u32 flags`.
    - The WinFile extension (format 2, no version byte) is a size followed by a `u32` file offset of the object's data.
    - `ExtractBOOL` reads 1 byte [0x70019b00]. `DE_CGUIDPool` is a `u8` flag; if it's 1, a `u16` count and count×16 bytes follow [0x7001f360].
15. **Object data** at that offset is three `block`s (contents, references, hierarchy), then `ReadEXDataHeader`: a `u32` count, and per entry a `block` and a `u32`. [0x7004fbb0, 0x700511f0, vtable slot +0xAC resolved by `re/proto/vtable.py`]
    - `DE_CTransferObjectInfo::New` decompresses the contents **only when `flags & 2`** [0x70055140]. It then creates the object with `DE_CObjectFactoryManager::FindByPath(class_path)->NewObject()` and calls its `ObjProcessContents` (vtable +0xA0).
    - **All 65 files and 28,115 objects parse, and every compressed one passes its MD5 check** (`ctest`, test `de-all-files`).
16. **Class census:** 456 distinct class paths (`re/class-census.txt`).
    - The largest groups are TextureManager (3,327), `Image\Standard` (2,166), `DataChannel\UnitFloats` (2,152), Actor (2,070) and **`Noise2\DirectMusicSegment` (1,745)**, so audio is DirectMusic segments and needs a DirectMusic reimplementation.
    - Scripting objects: `Class` (255), `Behavior` (290), `ClassExecutor` (284).

17. **Class paths map to C++ classes.** Each factory's `PathAdd()` returns its path component and `ObjParent()` returns its parent factory, sometimes through the IAT for other modules. [ghidra `re/scripts/FactoryPaths.java` → `re/factory-paths.tsv`, `re/proto/factory_map.py`]
    - **All 28,115 objects resolve to one of 118 C++ classes** (`re/class-map.tsv`): 63 in Core, 20 Particles, 16 Creature, 15 OMF, 2 Session, 2 AudioPlayer.
    - The earlier "456 classes" census was an artefact: names containing spaces broke the whitespace split.
18. **References are a tag byte** [Core 0x70057690 `ExtractReference`]:
    - ≥ 0x32: local object, index = tag − 0x32. 1: `u16` local index.
    - 2, 3, 4: `u8`, `u16` or `u32` index into the agent GUID pool, meaning an object in another file.
    - Anything else: null.
    - Verified: `PFighterStats` refs `0x37` → Fighter object 5 = `BFighterStats`. [test]
19. **Behavior (`DE_CPCode`) v5 layout** [Core 0x70163d90 and element readers]: name, then the Import / Global / Members elements, then an `i32` count of (`i32` type 1=Method/2=Inclusion/3=Class + element chunk), then one `i32` parent link per element.
    - The links form a dotted method tree (`Ground.Attack.LeftPunchHeavy`).
    - **All 290 behaviors decode to original commented source, 5.4 MB in total** (`re/scripts-src/`).
    - The language is a C++/Java-like coroutine state language: `exEndFrame()` yields per frame; it has `master`, `inherit`, `replicate` and `final`.
20. **`Class` (`DE_CClass`)**: contents hold name, base factory path and a string pool of exported signatures. The references list the attached behaviors (BOOL-terminated). [Core 0x70135a90, 0x70135df0]
21. **Compiled bytecode is shipped.** EX key `VMC2` → payload of `u8` flag plus `block` [Core 0x70050130 `EXRequestData`]. 249 of the 255 Class objects have it. `DE_CClass::PrepareForExecution` loads it via `EXGet` and compiles only if it is missing [Core 0x7013abb0].
    - Container v13 [Core 0x70134530]:
      - change-info block
      - classes: `[name, sq layout-pos]`
      - intrinsics: `[sq class, signature]`
      - ref-members `[sq]`
      - per behavior a sized chunk [0x701370d0]: instances, compiled methods, base links, replicated vars
      - then globals and interfaces. Prototype: `re/proto/vmc2.py`.
    - A compiled method [0x7013de50] holds a `bool`, a name `block`, a **bytecode block**, 4 flags, conditional tables, instances, interfaces, 5 counters, the signature, an `i32` and replicated vars.
22. **Bytecode encoding** (interpreter `DE_CPCExecuter::ContinueExecutionInternal`, Core 0x7014eaa0, 15.6 KB, about 300 cases):
    - Each instruction is an `i32` opcode followed by typed operands (`ExtractBYTE/CHAR` = 1 byte, `WORD/SHORT` = 2, `DWORD/INT/FLOAT` = 4).
    - Opcodes 2 and 3 carry inline data of an operand-given length. Opcode 313 has a conditional `u16`. Opcode 310 has no case (no-op). Opcodes 109–112 are jumps (pc = code base + operand).
    - **All 8,279 compiled methods in the 223 dumped classes disassemble exactly to their end; 131 distinct opcodes are used.** [`re/proto/disasm.py`, operand table generated from the decompile by `re/proto/opcodes.py`]
    - Example: `float Health()` = `op1(8,0)`, `op66(4,0,4)` (copy member@0 → sp+4), `op5(0,4,4)` (copy to the return slot), `op319`.
23. **Compiler pieces exist:** `PCParser::yyparse` (yacc) and `PCScanner::GetToken` are in Core, which gives a route to compile the 6 Class objects without VMC2. `DE_CClass::SetupGlobalPCClassDefinitions` (9.6 KB) plus the factory `Init`s define the native script API.

24. **Executor model** [Core 0x7014e260 / 0x7014e580 `InternalExecute`, 0x7014eaa0]:
    - A frame is `[return][params][locals]`. A method's counters give frame size (`+0x3c`), param bytes (`+0x40`) and return bytes (`+0x44`). `IsInstant` = flag `+0x84`, `IsState` = flag `+0x90`.
    - op 1 is the prologue: it clears the return slot and locals, then suspends. Synchronous calls therefore run `ContinueExecution` twice.
    - op 305 (`exEndFrame`) suspends; op 319 returns.
    - Running off the end of the outermost frame restarts the default state, or finishes if the method is instant/has no default state. Inner frames pop to the caller; a "sync" frame returns to native code.
    - Class method index = position of the signature in the Class string pool (appended if missing).
25. **Intrinsics:** op 30 calls a native function with a pointer to its argument block (`[return][params]` for statics; `SmoothFastToStop(x)` = `1-(1-x)^2`).
    - Registration is `DE_CPCNodeClass::NewMethod(classNode, name, <Name>Caller)` plus `NewParameter` (type at `+0x3c`, 8 = float).
    - `re/native-api.tsv` lists 965 registrations (`re/proto/native_api.py`).
    - The bytecode calls 971 distinct intrinsics on 64 native classes (`re/intrinsics-used.txt`). The registrations cover 82% of call sites by name; the gaps are nested value types (`CVector`, `CText`, collision info) and `Register*State` / `Is*`.
26. **First native execution:** `engine/src/vm/executor.cpp` implements the local opcode set. Shipped `BFighterStats` bytecode (`Health`, `NormalizedHealth`, `NormalizedStamina`, `FighterLoseStamina` with branches and a parameter) runs and matches the source's math. [test `test_vm_fighter_stats`]
    - Script memory is a 32-bit arena (`vm::Memory`), because the bytecode assumes 4-byte pointers and peeks native structs at byte offsets.

27. **Images (`Image\\Standard`)** [Core 0x7018d850 `DE_CImage`, 0x70194420 `DE_CStandardImage`, 0x7018b4b0 `DE_CStandardImageCompressor::Load`, 0x7018b7a0 `SetupID`]:
    - Header: DE_CImage v5/v6 holds name, type, ResX, ResY, BOOL, float, BOOL, channel mask (v6 adds two ints).
    - Pixels are EX entries keyed by **2 raw bytes {compressor id 0, sub-image index}**, with no NUL. (The earlier key handling stripped NULs and lost index 0; fixed.)
    - Payload: `u8` version 2, a method-7 compressed block, then `[i32 channel, ResX*ResY bytes]...` terminated by −1. Channels are **planar 8-bit**: 0/1/2 colour, 3 alpha, 4 luminance.
    - Index > 0 are sub-images stored in this owner (owner/index assignment comes from the hierarchy, not yet decoded). Their size is currently inferred from the payload layout.
    - **All 2,271 images decode: 6,932 levels, 585.5 Mpx.** 38 sub-image entries on 20 images use obsolete "DZip" (method 5), which the original engine cannot read either.
    - Robot skins are 1024² with flat R/G/B regions, which look like colour-slot masks (*inference*: recoloured per pilot via `ImageFilter\\OMF2Fighter`).
28. **Meshes (`Mesh\\Standard`)** [Core 0x7012ec00, 0x7012f6b0]:
    - v6 contents hold only the counts. Geometry is in the raw EX `ObjExtCon`: chunk v1 with `u16` nverts × `f32[3]`, then `u16` nfaces × {3 × (`u16` vertex, `u16` adjacent face), `u32`}.
    - Call targets confirmed by mangled overloads (`re/scripts/CallsIn.java`). There are no UVs in the mesh; they must come from the TextureProcess/material side.
    - **All 966 meshes decode: 409,219 vertices, 692,774 triangles** (192 have no geometry). Verified visually (`re/images/JaguarTorso.png`).

29. **Hierarchy block** [Core 0x7003c110 `DE_CObject::ObjProcessHierarchy`, 0x70057a80 `ExtractChildReference`]: a v1 chunk holding a BOOL-terminated list of child references (same tag encoding, local only). This gives each file a full object tree (`deobj-dump tree`).
    - A fighter model is a `FighterModel` holding its images (RGBMain, RGBScaled, ReflectionMask, Bump), an LOD switcher, and 3 LOD meshes (`Paint1Game2500/1300/750`).
    - Each mesh holds a `TextureProcess\\MultiStage` material with `TextureManager` stages, plus 15 per-bone `DataChannel\\UnitFloats` deform weights.
30. **TextureManager** extended contents [0x70131f80] are v1: `i32` n, then n × {`u32` mesh face, 3 × (`f32` u, `f32` v)}. Each stage therefore also defines which faces it covers.
    - References [0x70131c40]: after the DE_CObject chunk, an `i32` count + image references (often external, via the GUID pool).
    - Verified visually: all 8 robots render correctly textured (`re/images/robots.png`).
31. **Pilot recolouring** [OMF 0x350350e0 `DE_COMF2FighterImageFilter::Filter`, 0x35035ff0 `DE_CColorConversion::Update`]:
    - Robot skins are R/G/B masks; out = r·C0 + g·C1 + b·C2, clamped. The `Ci` are `DE_CPilot::UserDefinedColor` slots.
    - The tables are clamp(colour·256·i, 0, 65280) >> 8. The x87 constants (256.0, 0.0, 65280.0) were read from the instruction listing (`re/scripts/ListInstructions.java`), because the decompiler hides `__ftol` operands.
    - Note: REA's own analysis truncated this function at the first `__ftol` call (the same non-returning heuristic issue as item 12), so the Ghidra project with the fix was used.
32. **Actors** [0x7008fca0 `DE_CActor::ObjProcessContents`, 0x70025f70 `DE_CCoordinateSystem`]:
    - v7 holds name, `f32` position[3], and 9 floats = an orthonormal rotation (rows), then flags. DE_CObject writes no contents chunk.
    - References [0x7008ff90]: after the DE_CObject chunk, a BOOL-terminated component list (meshes drawn by the actor).
    - Scene assembly (`engine/src/de/scene.cpp`): world = parent ∘ local, with folders as identity. Meshes = child meshes + referenced meshes, de-duplicated. Materials = MultiStage children.
    - **Arenas render natively** (`openbg-arena`): Desert, City, Iceberg, Volcano, Canyon, SpaceStation.
    - *Inference / simplification:* each material is drawn as base × 2·lightmap; the stage blend modes are not decoded yet.

33. **Skeletal animation** [Core 0x701bbf70 `DE_CAnimationSequenceGroup::ObjProcessContents`, 0x701bcd80 `DE_CStream::ProcessContents`, 0x700274c0 `DE_CQuaternion`]:
    - Bank v4: name; sequences {name; streams {`u16` channel; v1 chunk: n × {t, x, y, z}; n × {t, quat}}}; channels {name, BOOL, BOOL, `i16` parent, rest position, rest quat}.
    - Quaternions are (x, y, z, w). Time is normalised to 0..1.
    - Jaguar has 102 moves and 142 channels: the 15 bones plus cameras, grab handles, markers and an `InitialStanding*` pose.
    - The root channel `Body` carries the move's placement in the animator's scene (root motion). The viewer holds it at the origin. *Inference:* in-game it drives the fighter's movement.
34. **Skinning** [0x701201e0 `DE_CActorDeformInfo`, 0x70120d50/0x70120f50 `DE_CDeformer`, 0x701168a0 `DE_CUnitFloatsDataChannel`]:
    - DeformInfo v3 has BOOL-terminated deformers, each with a model-space bind position and rotation. The references give each deformer's bone actor.
    - Weights are mesh children `Deform<Bone>VertexData`: a UnitFloats v1 block, count 1 × element size = vertex count, one byte per vertex (0..255).
    - Linear blend skinning, `Σ w·Pose·Bind⁻¹·v` with normalised weights, reproduces coherent poses for all 8 robots (`re/images/jaguar_moves.png`, `all_kicks.png`). The blend formula is *inferred* (verified visually only).
    - Bone counts differ: Force 11, Warlord 12, Gargoyle 17 (plus a separate wing rig, `WingDeformInfo` / `WingAnimationBank`, not yet applied).
    - Playback rate per move is not decoded; the viewer uses about 1.25 s per move.

35. **Script runtime** [Core VM executor; engine `src/vm/executor.cpp`, `src/game/runtime.cpp`]:
    - Virtual calls (op 36) dispatch by vtable slot; states override methods with nested, state-scoped methods, so `ObjectSpawn` must resolve against the most-derived class (`BJaguar` → `BFighter` → `BObject`).
    - The op 1 prologue (`SetupStack`) constructs instance-typed locals (e.g. event objects) in place; leaving them null breaks `this` in later native calls.
    - Op 61 yields a per-brain "final" class instance (64 bytes here).
    - Fighter flow: `Entry` → `FighterJustCreated` (waits) → engine calls `ObjectSpawn` → `Air.FallFromSpawn` → `Air.Fall` → `Ground.Stand`. Input is switched on by a `CGenericEvent` sent to `Session` (INT1 = 1).
36. **Input sequences** [Creature 0x15006a90 `DE_CJoystickInputSequence::Verify`, 0x150020c0 `DE_CJoystickInputManager::Tick`]: the manager keeps one 8-byte record per input change {`u16` buttons, `u16` directions, `u32` age}. Tick inserts new records at age 0 and adds 1 to every older record each frame, so the counter is *frames since that input began*, not how long it was held. Verify walks requirements last-to-first against records newest-first. A record must match the buttons (`(buttons & mask) == value`) and the directions (any of the 9 bits, 0 = any). Two bounds apply: the record's own age (fields 3/5) and its *gap*, the age of the record just newer than it, i.e. how long ago it ended (fields 4/6), with 0 max = unbounded. Once a bound is met it stays met while the same requirement moves on to older matching records. One record can satisfy several consecutive requirements. A plain tap is therefore {released, gap ≤ 15} → {direction not forward, age ≤ 15} → {pressed, age ≤ 15}. Reading the counter as hold duration made old presses count as new (repeating attacks); reading it as age fixes that.
    - Buttons [OMF `Is*ButtonDownCaller`]: 0 left punch, 1 right punch, 2 left kick, 3 right kick, 4 jump, 5 duck **and** evade (one button; evading is duck + a direction).
    - `Get2DOrientation` [Creature 0x15001a20] reads the newest record's direction bits: 0 up, 1 up-right, 2 right, 3 down-right, 4 down, 5 down-left, 6 left, 7 up-left, 8 neutral. `GetWalkAction`/`GetJumpAction`/`GetPreJumpAction` [OMF 0x35027310/0x35027400/0x35027510] map those to movement actions (walk: up 1, up-left 2, up-right 3, right 4, left 5, down 8, down-left 9, down-right 10; pre-jump: forward 0x13, back 0x14, else 0x10).
37. **Fighter movement** [OMF 0x35024910 `DE_COMF2Fighter::ObjProcessContents`, 0x35027ab0 `WalkStandard`, 0x350288b0 `BeginJumpStandard`, 0x35027620 `JumpStandard`, 0x350258e0 `TurnLeft`, 0x35025af0 `Propel`, 0x35039970 `DE_CFighterPhysics::Tick`]:
    - The fighter's last contents chunk (v2) holds its movement stats as floats: turn max/step, walk speed, walk-turn max/step, back speed, back-turn max/step, air turn max/step, air forward/back push, then 6 not yet identified, then jump forward/back/up and super-jump forward/back/up. Jaguar: turn 3.5°/frame (step 0.17), walk 1.0, back −0.9, jump up 1.55, forward 0.57, back 0.4.
    - `WalkStandard` ramps the turn rate towards its max by the step, calls `TurnLeft(deg)` (positive = left), and `Propel(forward, left)` eases local momentum towards the target speed by traction × 0.1 × |target| per frame. Back speeds are scaled by 0.75.
    - `BeginJumpStandard` adds the jump's up speed to the momentum and sets the forward/back speed. In the air, gravity is 0.037 units/frame² × a multiplier that recovers towards 1 (`SetGravityRecover`). The scripts' `FPS` constant is 60.
    - Ground friction [Core 0x701dc6d0 `ApplySingleSurfaceFriction`, OMF 0x3503b1e0/0x3503a5b0]: friction = material (1) × traction; while not propelled, momentum loses 0.1 × friction of itself per frame and stops once under 0.1 × friction². No friction while propelled.
    - `Propel` cancels momentum not aligned with the wanted direction (× traction × (1 − cos)), steers up to 0.2 × traction of it onto that direction, then eases each axis. `FallStandard` is `JumpStandard`, which also adds the fighter's extra air gravity (+0x52c × 0.037) every airborne frame.
38. **Animation preludes** [Creature 0x150159c0 `DE_CCreature::AnimActivatePrelude`]: the creature captures its current pose (`AnimCaptureAsInitial`), and anim time 0..1 then blends from that pose to the new sequence at the given lead-in time. `AnimActivate` starts the sequence proper. Playing a prelude as the sequence itself made moves flicker through a whole cycle in ~10 frames.

39. **Pilots** [OMF 0x3504b450 `DE_CPilot::ObjProcessContents`, 0x3504bf50 `CalculateAIValues`, 0x3502fc70 `CVariedStat::GetValue`]:
    - Last contents chunk v4: 3 × {colour reference, f32} (90 bytes in every shipped pilot), then power/agility/endurance/focus (0-100; `Normalized*` = stat / 100). Then 31 AI stat descriptors {u8, squeezed level 0-8, variation 0-5, wave 0-3}, then 2 floats.
    - Each AI stat is a `CVariedStat`: value = base + amplitude × sin((time_ms + phase) × frequency × {0.001, 0.002, 0.004, 0.015}[wave]). Base = {0, .1, .3, .6, 1, 1.3, 1.6, 2, 3}[level]^exponent, with exponent and phase/frequency fixed per stat in `CalculateAIValues`. Amplitude = base × {0, .1, .2, .4, .7, 1}[variation]. Exceptions: attack range maps its level to {30, 50, 75, 120, 160, 220, 300, 400, 600} units; movement urgency uses {.3, .5, .75, 1, 1.3, 1.7, 2, 3.5, 6}; perception stats vary around 1 by quality.
    - AI quality degradation = clamp(1 − (difficulty + pilot offset) / 3.5, 0.01, 0.99). Difficulty is the app's setting (`DE_COMF2Manager::AIDifficulty`: 0 Rookie, 1 Amateur, 2 Veteran, 3 Champion, 4 World Champion); scripts add a per-pilot offset with `SetAIDifficultyOffset`.

Every command has priority 1 (`+0x48`). So `AttackBestEnemy`, called every frame, piles up attack commands that the pilot only clears when it changes state.
   - **Sort** runs only when the list has changed. Each command's sort key starts at its priority. `MoveTo::ModifySort` sets the key to 0 while the creature is within the required distance of the command's current move-to position. The list is then bubble-sorted by key, highest first, keeping insertion order on ties.
   - **Reassign.** With the type mask 0x3e, the first sorted command is executed, then each later command whose type has not been taken yet. So only the first command of each type takes part, and for attack commands that is the oldest one.
   - **Execute** picks the controller's executor with the highest confidence. Attack and aquire commands score their value (`+0x78`: aggression or urgency); move and look score 1. A command whose confidence is strictly greater than the current primary's becomes the primary, and the old primary moves to the backup list. Otherwise the command is added as a backup, unless its confidence is 0, in which case it is dropped.
   - **Tick** (once per creature tick):
     - Every command runs `Update`; a move-to command takes its next navigation-path position.
     - The primary runs. If it acted (did not call `ExecutorDidNothing`) and is an attack or aquire command, nothing else runs.
     - Otherwise every backup runs in list order.
     - A controller info's counter (`+0x3c`, never reset) goes up when the primary did nothing (above 8: reassign) or when there is no primary (above 20: reassign).
     - Masks: `+0x90` 0x3e, `+0x98` 6, `+0x9c` 0x30.
   - **Hookup executor:** `ExecutorDidNothing` clears `+0x30`, which `Tick` sets before each hook call. `DeltaTick` is never registered for this object (only Core calls `AddDeltaTick`).
   - **AttackBestEnemy** walks the creature's known needs (`+0x168`), taking each need's owner:
     - The score is distance / (need desire(4) + 0.01). The current target's distance is scaled down by its age, as already ported.
     - An owner in the pilot's Love list (`+0x348`) has its distance multiplied by Valor (`+0x7a8`) × 2. One in the Hate list (`+0x35c`) has it divided by Anger (`+0x768`) × 2.
     - Owners with `GlobalInterest` ≤ 0 are skipped.
     - Only single-player sub-sessions fill the lists (`AddIfAbsentHate`).
   - **Attack** changing the target sets the quality-degradation offset (`+0x3d0`) to −(q − 0.5) when q > 0.5, else 0. `NormalizedAIQualityDegredation` returns q + offset. For a user-controlled target the offset becomes 0 when a master-session member's vtable slot 0x154 returns 0; I couldn't identify that method.

116. **Stream geometry, primitive meshes in world space, ProcessEvent** [Particles `DE_CStreamParticleRenderer::DE_CInstanceInfo::Process` 0x400172b0 (disassembled), Core `DE_CPointStreamer::DE_CInstanceInfo::Process` 0x701d17f0, `ProcessEventCaller` 0x70046230, `DE_CActor::ProcessEvent` 0x70090ed0, `DE_CObject::ProcessEvent` 0x7003b610, OMF `DE_COMF2Fighter::ProcessEvent` 0x35024d30, Core `DE_CPrimitiveGeneratorMesh::Process` 0x7012bde0, `CTextPrimitive::Setup` 0x7012df90]:
   - **Stream fields.** The first int is the texture mode (+0x70), the second the colour mode (+0x74): `+0x74 == 5` picks the intensity channel and the colour switch (0x40018117, cases 1-5) loads +0x74. Shipped pairs: texture 0/2/4, colour 2/3/4/5.
   - **Colour modes** (jump table 0x400185dc): 1 all four × age; 2 × (1 − age); 3 constant; 4 the colour value at age, rgb × alpha, alpha 1; 5 rgb × alpha × intensity, alpha 1; 0 a constant written once.
   - **Texture modes.** 0: each quad the whole image, written once. 2: frame = serial & 15, u = frame × 0.25 (wraps), v = (frame >> 2) × 0.25. 4: v = age × +0x78 + time × +0x7c, where the time is the one handed to `SetTime` (scene ms; the data's +0x7c are scroll rates like -0.003 and 0.0001). Modes 0-2 draw four vertices per particle (separate quads); the others share a strip unless breaks without a gap. The joints are averaged either way, so the geometry is the same.

A segment's half-width is size (its first particle) × width × focal / depth of its second. Its direction is the sum of its own and the previous segment's screen delta (+0.001 on the length). An actor passes it to each property (the script event relays among them) and then to `DE_CObject::ProcessEvent`, which handles only the editor's drag-and-drop events. `DE_COMF2Fighter::ProcessEvent` forwards OMF2 types 1-10 to its recipient lists; the projectiles' arena surface hit (0xb) has no handler.

121. **Sound speakers** [AudioPlayer `DE_CDirectXSpeakerElement::Update` 0x100047b0, `Play` 0x10005010, `Activate` 0x10004460, `SetActiveNoise` 0x10004370, `CreateNewAudiopath`, `DE_CDirectXListenerElement::Update` 0x10005490, `DE_CDirectXAudioPlayerFactory::ProcessEvent` (DirectSound setup); Core `DE_CScene::PlayNoiseSphere` 0x70072b70, `PlayNoiseAmbient` 0x70072c20, `DE_CSpeaker::NewNoisePlayerSphere` 0x70219e70, `DE_CSpeakerElement::GetNoiseVolume` 0x70215770, `DE_CSphereAffector::IsTouching` 0x7008a1b0; constants at AudioPlayer 0x1000fac4..0x1000fae8]:
   - **Speakers.** `PlayNoiseSphere` makes a sphere affector at the point carrying a speaker with the noise; `PlayNoiseAmbient` does the same at the origin with a 1e7 hotspot and falloff. The speaker element's volume comes from the sphere (`IsTouching`, vtable +0x164): 1 within the hotspot, 1 − (d − hotspot)/(falloff − hotspot) out to the falloff, else 0.    - **Updates.** Every frame `Update` adds falloff/(distance + 1) × rate × frame ms to +0xac (10000 with no falloff) and does nothing more until it passes 200; then it zeroes it. The listener is positioned and oriented every frame (`SetPosition`, `SetOrientation`, deferred, committed in `PlayAudio`).

   - **Not used.** Nothing calls `SetVelocity` on a buffer or the listener, `SetDopplerFactor` or `SetRolloffFactor`, so there is no Doppler effect (zero velocity), and there is no occlusion or obstruction. Each sound gets its own duplicated buffer; AudioPlayer has no voice limit of its own.

132. **Compiling classes shipped without VMC2** [Core `DE_CClass::PrepareForExecution` 0x7013abb0, `PCParser::yyparse`, `PCScanner::GetToken`; `DE_CPCodeMethod::ProcessContents`; `DE_CConstantList::NewConstant` in the factories' `Init`]: `vm/compiler.cpp` compiles them; checked method by method against classes that do ship VMC2 (the North American Open's sub-session: 94 of 95 methods identical in opcodes, call targets and literals; Redemption's, PCarManager, PSpinningBlade, PGunTrigger, PAirStrikeMissile alike).
    - **Method elements.** After a method element's source come two bytes: the first is 0 for a virtual method (its signature takes a vtable slot, slots numbered in order of appearance), the second set for an excluded element (Templates, Setup) whose subtree is not compiled. The leading u32 is 0 for a state, 1 for an instant method, 2+ for templates and settings (not compiled). A behavior's compiled methods are its method elements depth first, each followed by those nested in it; interface calls (op 37) number them in that order. Behaviors whose elements name method templates (the robots', the session masters') compile more methods than they have elements.
    - **Names.** A bare call goes to the methods nested in the running state and its enclosing states, then to the most-derived behavior's top-level method (a later behavior's `SetupMatch` replaces an earlier one's though neither is virtual); `.A.B()` paths name nested states. Overloads are chosen by argument types. Members are laid out from the last behavior to the first; object-reference members (non-value native classes) are ref members (ops 62/64, their classes listed in VMC2's ref-member table) and such locals in states local refs (ops 20-22, counted in the method's second count). Finals are inlined; class-typed finals (`final CNamedHandle g_X="..."`) are final instances (op 61). `<Return>` in a string literal becomes a newline.
    - **Code.** Expressions evaluate into frame slots: a call's receiver, then its arguments 4 bytes apart (a script method's return slot first); a binary operator's right operand 8 bytes after the left, or a numeric local used in place; the left operand's type decides and the right is converted (literals folded to it). `&&` short-circuits, `||` does not. Compound assignment to a numeric local works in place. Primitive array elements are written through `<ArrayElementPosition>` and op 7, reference arrays through `<ArrayElementSet>`; native fields with ops 47/50, embedded native values (CAttackInfo's vectors, a coordinate system's axes) with op 229. A native value passed where a primitive is wanted goes through its `Conversion()` operator; an instance passed to a state method is copied (op 42).
